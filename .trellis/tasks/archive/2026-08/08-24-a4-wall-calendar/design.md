# A4 竖版中国月历生成器：技术设计

## 1. Architecture

项目采用纯前端静态架构：

- **构建与开发**：Vite。
- **界面**：原生 HTML、CSS 和 JavaScript，不引入组件框架。
- **日历数据**：`chinese-days`，提供公历转农历、二十四节气及中国放假/调休数据。
- **PDF 输出**：普通用户使用浏览器原生打印；开发辅助脚本调用本机 Chrome 的 headless print-to-PDF。
- **部署**：仅需在本机启动 Vite 开发/预览服务，不依赖后端。

保持原生前端方案可减少产物体积和维护成本，也足以支撑单页年份选择与 12 张打印页面的交互复杂度。

## 2. Module Boundaries

当前原型代码较小，MVP 保持以下边界：

- `index.html`：页面语义骨架、年份选择器和打印入口。
- `src/main.js`：年份范围、日历数据适配、月份网格计算、DOM 渲染和交互。
- `src/style.css`：屏幕外观、A4 页面尺寸、打印分页、日期状态和图例。
- `scripts/export-pdf.js`：可选的本地全年 PDF 自动导出。
- `README.md`：本地启动、构建、打印和数据范围说明。

若数据适配或验证逻辑继续增长，应从 `main.js` 抽出纯函数模块，避免 DOM 逻辑和日期规则互相耦合。

## 3. Data Flow and Contracts

1. 页面从 URL `year` 参数或当前年份得到初始选择。
2. 年份必须落在法定放假数据完整覆盖的区间内；当前依赖版本为 2004—2026。
3. 生成器按年查询放假日期集合，再按月构建周一开头的日期网格。
4. 每个有效日期从数据源取得：
   - 农历年月日；
   - 当日节气（若有）；
   - 放假名称和是否休假；
   - 是否为调休补班。
5. 渲染层将状态映射为稳定的 CSS 类：普通、放假、节气、放假与节气重叠、补班、当日。
6. CSS `@page` 固定为 A4 portrait，每个 `.month-page` 强制独立分页。

关键规则：

- 普通工作日不得因 `getDayDetail().work === true` 被误判为调休补班；补班还必须具备所属假期元数据。
- 假期名称从依赖返回的多语言字段中取中文部分。
- 农历初一显示农历月份，其余日期显示农历日名。
- 数据范围外的年份不出现在选择器中，URL 非法年份回退到受支持年份。

## 4. Print Design

- 页面物理尺寸为 `210mm × 297mm`，使用约 10—13 mm 安全边距。
- 月份标题和星期栏保持清晰层级，其余纵向空间全部交给日期网格。
- 月份根据实际占用自然使用 4—6 行；各行平分可用高度。
- 放假使用低饱和淡红，节气使用低饱和淡紫；重叠时用双色分区。
- 文字和网格线需保留足够打印对比度，辅助文字避免小于普通打印可读尺寸。
- `print-color-adjust: exact` 尽可能保留背景；README 同时提醒启用浏览器“背景图形”。

## 5. Compatibility and Failure Handling

- 主要支持当前 Chrome/Edge/Safari 的页面预览与打印。
- 浏览器打印是正式路径，因此不依赖用户拥有固定 Chrome 安装路径。
- CLI 导出脚本允许通过 `CHROME_PATH` 覆盖默认路径；找不到 Chrome 时应给出清晰错误。
- 数据依赖升级后必须重新执行关键日期回归检查，不能仅依赖构建成功。
- 新年份放假安排未进入数据源之前，不扩展选择范围。

## 6. Trade-offs

- **不使用后端**：部署简单，但法定假日不会自动在线更新，需要升级依赖并重新构建。
- **浏览器原生打印**：跨平台且无需额外 PDF 库，但用户需正确选择 A4、100% 缩放和背景图形。
- **原生 DOM 渲染**：依赖少、产物小；若未来增加事项编辑、多模板或国际化，再考虑组件化框架。

## 7. Rollback

所有改动均为静态前端与开发脚本，不涉及持久化数据或迁移。若视觉迭代导致打印回归，可按文件回退 CSS；若依赖升级导致日期数据异常，可锁回已验证版本。
